# Pruebas y benchmarks
## Capas
Unitarias, lexer/parser, semántica/tipos, conformidad, integración, regresión, diferenciales entre modos, fuzzing, rendimiento, instalación y usabilidad.

Cada bug corregido debe tener una prueba de regresión cuando sea viable.

## Benchmarks
Publicar fuente, versión, hardware, SO, configuración, comandos, calentamiento, múltiples ejecuciones y dispersión. Separar compilación, arranque, ejecución y memoria. No afirmar superioridad sin evidencia reproducible.
